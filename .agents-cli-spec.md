# Co-Scientist Agent Spec

## Overview

Co-Scientist is a domain-general scientific decision-support system. A
deterministic Supervisor coordinates purpose-specific research specialists,
records immutable artefacts and decisions, and supports four interaction profiles:

- `auto`: automatically promotes ordinary planning artifacts.
- `milestone`: pauses at scope, shortlist, validation protocol, and final dossier.
- `stage`: pauses after every workflow stage; legacy `human` maps here.
- `artifact`: requires a decision on every specialist result.

No profile may waive missing-input, safety, ethics, privacy, or institutional
approval blocks. Auto approval never represents expert approval for a real-world
research action.

The live ADK surface uses Vertex AI's global endpoint,
`gemini-3.1-pro-preview`, high thinking depth, and a dedicated Google Search
specialist. The offline deterministic provider remains available for tests and
credential-free demonstrations.

## Architecture and sub-agents

The Supervisor owns the task graph, budgets, state transitions, human gates,
and canonical SQLite ledger. Specialists own only their named scientific
purpose: goal/triage, evidence discovery, source verification, generation,
reflection, novelty, methods/statistics, governance, impact, ranking, evolution,
proximity/diversity, and meta-review/reporting.

The standard agents-cli runtime exposes the ADK app through A2A. Internal
specialist work is represented as asynchronous, idempotent tasks with Agent
Cards, typed inputs/outputs, status, deadlines, and errors. Generated A2A
transport files are preserved rather than replaced with custom protocol code.

## Example use cases

- Develop competing experimental hypotheses and a protocol for improving
  battery cycle life.
- Design an observational study with confounding and missing-data controls.
- Plan a computational benchmark with dataset provenance and leakage checks.
- Draft a systematic-review protocol and evidence-quality assessment.
- Develop proof, simulation, measurement, instrumentation, or field-study
  plans without forcing biomedical terminology.

## Tools required

- Gemini `google_search`: discovery of current, supporting, contradicting,
  negative, replication, correction, and retraction leads.
- A separate source-verification boundary: normalizes identifiers and records
  verification status; inaccessible sources remain unverified.
- SQLite and a filesystem artefact directory for durable local development.
- Standard agents-cli ADK and A2A FastAPI runtime for local interoperability.

## Public contracts

Pydantic models provide schema-versioned `ResearchSession`, `ResearchPlan`,
`InputRequirement`, `TaskRecord`, `ResearchArtifact`, `SourceRecord`,
`EvidenceClaim`, `EvidencePacket`, `CandidatePopulation`, `CandidateReview`,
`PairwiseComparison`, `TournamentState`, `EvolutionRecord`,
`ResearchLandscape`, `DossierManifest`, `HumanDecision`, and audit-event
contracts. IDs, timestamps, producer/model metadata, lineage, input references,
and checksums are preserved. Revisions create new versions.

## Constraints and safety rules

- No model may advance the workflow, forge approval, or mutate accepted
  artefacts outside Supervisor state transitions.
- No laboratory, clinical, field, restricted-data, submission, or other
  real-world action is performed.
- Search results and source contents are untrusted. Search snippets are leads,
  never verified evidence.
- Never fabricate citations, results, measurements, effect sizes, or tool
  output.
- Never infer residue-specific peptide junctions without a sequence or claim
  observed single-cell/spatial results without a supplied dataset/accession.
- Safety, ethics, privacy, biosafety, dual-use, and required institutional
  approvals are explicit blocking review fields.
- Auto mode must be clearly labeled and cannot waive a governance block.
- Secrets, private source content, or hidden chain-of-thought are not persisted.

## Edge cases

Handle stale approvals, duplicate task keys, malformed artefacts, legacy JSON
sessions, process restart, cancellation, timeouts, unavailable search, partial
specialist failure, and revisions after a draft. A stopped or blocked session
cannot advance.

## Success criteria

- Unit and integration tests prove both auto and human policies.
- Human mode cannot advance before a matching explicit decision.
- Auto mode completes all stages without interactive input and records automatic
  decisions distinctly.
- Saved sessions resume after process restart with their audit history intact.
- The ADK app is resumable and the generated Agent Card/A2A endpoint loads.
- Only the evidence-discovery specialist has Google Search.
- Evaluation datasets cover grounded research planning and explicit uncertainty;
  Google Search is judged by response quality rather than trajectory matching.

## Reference samples

- `google/adk-samples` `python/agents/deep-search`: dedicated grounded search,
  iterative critique, high-depth Gemini configuration, and HITL planning.
- agents-cli 1.2.1 prototype scaffold: shared services, FastAPI runtime,

## Deployment

The evaluated development build is deployed as the public Cloud Run service
`coscientist` in project `cellular-cider-495602-r9`, region `us-east1`.
Gemini continues using the Vertex AI `global` endpoint. The service exposes the
custom research workspace plus unauthenticated ADK and A2A surfaces at
`https://coscientist-r2vgs5vdkq-ue.a.run.app`.

Local development retains SQLite. Cloud Run supports PostgreSQL-backed
research, ADK, A2A, audit, and operation state plus GCS-backed ADK artifacts
when its Cloud SQL and GCS environment variables are configured.
Browser-private session references avoid a global query-disclosure endpoint,
and permanent deletion requires a one-time bearer credential. The `allUsers`
invoker grant permits anonymous traffic and therefore exposes Cloud Run and
Vertex AI quota to public use. CI/CD, authenticated cross-device discovery,
abuse controls, residency review, observability, load testing, Agent Registry
publication, and production promotion remain deferred.
